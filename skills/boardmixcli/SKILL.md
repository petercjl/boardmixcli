# BoardmixCLI capability manual

Input: explicit operations, Boardmix file keys, local PNG/JPEG/WebP/MP4 paths and object GUIDs, authorized by the user. Strategy: discover the installed contract, connect the selected editor, execute atomic operations and verify readback. Output: JSON receipts and verified Boardmix state. The calling Agent or application Skill owns business methods, material selection, ordering and layout.

## Main line

1. Resolve this Skill directory from the host's actual loaded resource path. Use Node.js with its target-owned `.runtime/bin/boardmixcli.mjs`; never infer a different Agent's installation path. Read this Skill’s `capabilities.json` and `adapters/generic.json` to resolve the logical execution and desktop features from the current host. Run `version`, `capabilities --json`, and `doctor --json`. In a source npm checkout, resolve the canonical runtime through the package CLI instead. Node.js >=22, local filesystem, loopback HTTP and an authorized browser CDP connection or desktop console access are required. Any Agent with these capabilities may use the generic adapter. Native desktop execution is tested on macOS Boardmix 1.7.2; other desktop platforms remain unverified.
2. For local inspection, `image.list --directory ABSOLUTE_DIRECTORY` returns supported image filenames in natural numeric order; `image.inspect --file ABSOLUTE_PNG` returns source dimensions and SHA256. Caller decides whether this order suits the task. For editor actions, read the runtime's `CONTRACT.md` before the first write to obtain exact flags and response/error contracts.
3. Start `serve --session NEW_ABSOLUTE_PRIVATE_FILE`, or reuse a confirmed live session. For the default browser route first run `browser.ensure --json`. It starts or reuses Chrome on 9223 with the persistent home-relative `.dianshang-chrome-profile`, opens Boardmix, and checks login. On AUTH_REQUIRED relay the returned prompt to the user; after user login run `auth.wait --wait-ms 60000 --json` or repeat browser.ensure. Continue only on state ready. AUTH_STATE_UNKNOWN requires page/load diagnosis, never assumed login. Automatic launch is macOS-only; an explicitly selected alternative endpoint remains caller-managed. Then use the returned endpoint: `browser.targets --endpoint URL` discovers Boardmix app tabs; `browser.open --endpoint URL --file-key KEY` opens a specified existing file; `browser.connect --endpoint URL --session FILE --file-key KEY` attaches it without visible DevTools. The endpoint must use loopback and must belong to the intended browser. Verify `status` and `board.info` identify the exact file. Read the browser connection contract in CONTRACT.md. Missing target, ambiguous tabs or a changed front-end build stops this branch; preserve the selected host. For explicitly selected desktop mode, use authorized native controls to execute the bootstrap once in that editor's Console, then minimize the specific DevTools window and verify the board is visible. Console connection is a fallback prerequisite, not a window that stays in front throughout the task.
4. Execute only caller-selected operations: file create/name/open/close; Frame/text creation; single or batch PNG/JPEG/WebP import; native MP4 import; object get/move/resize or batch placement; explicit viewport fit. Every editor command requires `--session` and `--file-key`. GUID sessionID/localID are separate numeric flags. Move uses absolute top-left board coordinates. Resize sets both dimensions and preserves aspect-ratio lock. Inspect each receipt, then read object/file state to verify the requested change before proceeding.
5. Prefer the batch operations in CONTRACT.md for multiple explicit inputs: inspect up to 1000 files, import up to 20 with a durable receipt, read up to 1000 GUIDs, or place up to 200 objects. Match returned caller keys and GUIDs; keep one write in flight per editor. Save returned GUIDs before layout verification. Repeat a batch import only with its original input and receipt; unresolved outcomes require inspection, not a new receipt.
6. Report actual file identity, operations, verified state and unresolved outcomes. For browser close, use browser.close with its save guard; for desktop close, use board.close and verify the file is absent from the desktop's open-file tabs after the close receipt. Fit animates asynchronously, so an immediate viewport value may precede the final visual state.

## Recovery and boundaries

- Missing Node, desktop controls, console access, login or supported front-end build: return CAPABILITY_UNAVAILABLE / AUTH_REQUIRED / FEATURE_UNSUPPORTED with the prerequisite. Resume at step 1 or 3 after resolution; do not invent a different adapter.
- File create or image import timeout: outcome may be unknown. Inspect the operation receipt/outcome and actual file/object state before any new mutation. Avoid duplicate creates/imports. Resume at step 4 only when the outcome is known.
- Protected local destination: preserve unmanaged targets and edits; use CLI-managed skill status/install/update with the current Agent's explicit destination. Installation does not authorize Boardmix writes or paid service actions.
- Package update: read `.runtime/UPDATE.md`, reconcile only this selected installation, verify CLI/Skill/receipt versions and hashes, then refresh host discovery. A current verified receipt takes a read-only completion branch. Host discovery requires host evidence.
- New recurring integration failures belong in a separately authorized capability-package repair with tests. Business quality and layout rules remain owned by the application layer.

The runtime CONTRACT.md and capabilities.json are authoritative versioned operation references. This mechanical manual directly internalizes tested command behavior; it has no nested Skill or private knowledge-base dependency. Clean-context regression is separate from ordinary operation.

For remote images, image.download receives one explicit URL and a new output file. Frame and text operations are documented under Added capability operations in CONTRACT.md; native text bounds auto-fit, and Frame containment verification is geometric.

For videos, require ffprobe on PATH. Use `video.download --url HTTPS_URL --output NEW_FILE`, then `video.inspect --file FILE`. `video.import --file FILE --receipt NEW_RECEIPT --session SESSION --file-key KEY` uploads a native video and verifies the source MD5, video MIME and completed loading state. MP4 limit: 100 MiB. Persist the returned GUID before moving/resizing. Reuse the same receipt after interruption; VIDEO_OUTCOME_UNRESOLVED requires inspection and must not trigger another import. A poster alone does not satisfy video import. The caller owns region placement and playback acceptance.
